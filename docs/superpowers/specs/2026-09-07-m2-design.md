# M2 design — telemetry-driven routing across three vendors

**Date:** 2026-09-07 · **Status:** approved, pre-implementation
**Authoritative decisions live in `SPEC.md`.** This document holds the rationale and the
evidence behind the M2 amendments, so `SPEC.md` stays a spec rather than a decision log.

---

## 1. Why M2 changed shape

M2 as written was "second vendor, ladder, real ledger" over two CLIs, with a
self-estimated ledger. Three findings from CLI discovery changed that:

1. **Every vendor exposes real quota telemetry.** `SPEC.md` §7's premise — *"none of the
   four products exposes a clean usage API"* — was true when written and is false now.
2. **The Antigravity CLI exists and is fully headless.** §14 carried this as an open
   question and §5 called it a spike. It is answered: `agy` runs non-interactively, takes
   `--model` and `--effort`, and reports quota as a first-class command.
3. **The draft's adapter tests validate the wrong half of the subprocess boundary.** They
   mock `subprocess.run`, so they test our parser against JSON we invented and never test
   the argv we send. A fatal codex defect shipped green because of it.

## 2. Quota telemetry — the three mechanisms

Each vendor exposes utilization differently. The adapter owns that knowledge; `ledger.py`
stays vendor-agnostic.

| Vendor | Mechanism | Available | Verified |
|---|---|---|---|
| `claude` | `rate_limit_event` in `--output-format stream-json` | during a run only | yes — live probe |
| `codex` | `rate_limits` in `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-<ts>-<thread_id>.jsonl` | before and after a run | yes — live probe |
| `agy` | `agy -p "/usage" --output-format json` | any time, and free — 0 turns, 0 tokens | yes — live probe, `agy` 1.1.27 |

Claude, captured live:

```json
{"type":"rate_limit_event","rate_limit_info":{"status":"allowed_warning",
 "resetsAt":1789214400,"rateLimitType":"seven_day","utilization":0.59,
 "isUsingOverage":false}}
```

Codex, from the rollout file its own `--json` stream points at via `thread.started`:

```json
"rate_limits":{"limit_id":"codex","limit_name":null,
 "primary":{"used_percent":39.0,"window_minutes":300,"resets_at":1788817290},
 "secondary":{"used_percent":38.0,"window_minutes":10080,"resets_at":1789356153},
 "credits":{"has_credits":false,"unlimited":false,"balance":"0"}}
```

`primary` (300 min) and `secondary` (10080 min) map onto the 5h and weekly windows in
`SPEC.md` §3. A pool therefore has **several simultaneous windows**, which is why
`PoolConfig.window` becomes a list.

### Contract

```python
@dataclass(slots=True)
class QuotaWindow:
    kind: str                 # "5h" | "weekly" | "monthly"
    used_fraction: float
    resets_at: datetime

@dataclass(slots=True)
class QuotaObservation:
    windows: list[QuotaWindow]
    observed_at: datetime
    source: str               # "stream" | "session-file" | "command"

class AgentAdapter(ABC):
    def quota_probe(self) -> QuotaObservation | None:
        return None           # no telemetry: the ledger falls back to estimates
```

`AgentResult` gains `quota: QuotaObservation | None` for the post-run path. Estimates stay
as the fallback for any pool without telemetry — `copilot` is expected to need it.

### Reserve policy

A pool is ineligible once **any** of its windows reaches `used_fraction >= 1 - reserve`,
until that specific window's `resets_at`. `reserve_fraction` is per-pool in `orc.toml`,
default `0.15`. `--use-reserve` spends into it.

The reserve is decided before a run starts and never re-asked mid-ladder, so an unattended
run cannot block on a prompt and cannot lock the owner out of their own CLI. This is a new
hazard created by accurate telemetry: with estimates, over-spending was a guess; with real
numbers, an overnight ladder would reliably drive a pool to 100%.

Telemetry decides **eligibility only**, never preference. Candidate order stays
`orc.toml`'s, per `SPEC.md` §6, so the ladder logs remain clean routing data for v2
rather than being confounded by quota state.

## 3. Third vendor in M2

`agy` joins `claude` and `codex` in M2 rather than waiting for M4. It is the `volume`
lane, and it has the cleanest quota probe of the three, which tests `QuotaObservation`
against real variety instead of a two-point line.

`volume` sits **beside** the ladder, not below it: `[ladder] order` stays
`["standard", "quality"]`, and `volume` is reached only when every ladder candidate is
reserve-blocked. A cheap first rung would have consumed attempts from a fixed
`max_total_attempts = 4` budget and starved `quality`. As a fallback it costs nothing on a
healthy run and converts exhaustion from a failure into a degraded route.

### `agy` flag surface — verified against `agy` 1.1.27

`agy -p "/usage" --output-format json` returns two independent quota groups, confirming
`SPEC.md` §3's split of `antigravity_gemini` from `antigravity_claude`:

| Group | Models | Weekly remaining | 5h remaining |
|---|---|---|---|
| Gemini Models | Gemini Flash, Gemini Pro | 68.6% | 86.1% |
| Claude and GPT models | Claude Opus/Sonnet, GPT-OSS | 74.9% | 24.8% |

Note the polarity: `agy` reports `remaining_fraction`, codex reports `used_percent`, claude
reports `utilization`. `QuotaObservation.used_fraction` normalizes all three.

| Flag | Use |
|---|---|
| `-p` / `--print` | non-interactive run |
| `--model <slug>` | e.g. `gemini-3.8-flash-high` |
| `--effort low\|medium\|high` | the effort half of `(model, effort)` |
| `--output-format text\|json\|stream-json` | events for triage |
| `--json-schema` | forced JSON (M3 review findings) |
| `--print-timeout` | default `5m` |
| `--sandbox`, `--dangerously-skip-permissions` | permission model |
| `--continue`, `--conversation` | resume |

The docs table held up, but discovery still found three things it omitted:

- **No working-directory flag.** Unlike `codex -C`, `agy` has only `--add-dir`. The adapter
  must set `cwd` on the subprocess.
- **`--mode accept-edits|plan`**, the analogue of Claude's `--permission-mode`.
- **The reasoning tier lives in the model slug**, not `--effort`. `agy models` lists
  `gemini-3.8-flash-high` and no bare `gemini-3.8-flash`, so a candidate's `@effort` maps onto
  the slug suffix and `--effort` stays unset. The adapter's `live` test must confirm this.

**Remaining gate:** capture a real `stream-json` fixture from `agy` before writing the parser.

## 4. Defect register

Twelve defects in the `1a14ed9` baseline. D1–D5 were reproduced; the rest were read.

| id | defect | site |
|---|---|---|
| D1 | `-s workspace-write` and `--approve-for-me` are mutually exclusive; **every codex run exits 2** | `orc/adapters/codex.py` |
| D2 | `--output-format json` yields no tool events, so `tool_call_count`/`ran_commands` are always empty and triage can never return `dumb` | `orc/adapters/claude_code.py` |
| D3 | untracked `.orc/` dirties the tree, so a second run refuses to start; an agent's `git add -A` can also stage orc's own artifacts | `orc/gitops.py` |
| D4 | agent timeout is `[verify].timeout_s` (120s) | `orc/router.py` |
| D5 | `git diff` misses committed and staged work, so `files_edited` misreads and the reported diff can be empty | `orc/gitops.py`, `orc/router.py` |
| D6 | `log.jsonl` records the raw prompt; `SPEC.md` §13 forbids prompts and requires `prompt_hash`, `start_lane`, `triage`, `wall_s`, `est_usage` | `orc/router.py` |
| D7 | ledger never resets a window; `window_started` is written and never read, so `spent_units` accrues forever | `orc/ledger.py` |
| D8 | codex `usage` is never captured — the collector is `None` at the call site while `turn.completed.usage` is real | `orc/adapters/codex.py` |
| D9 | `find_config` only searches upward from the target, so `orc` cannot run on a repo outside this tree | `orc/config.py` |
| D10 | `test_file_snapshot` walks every `*.py` including `.venv`, is Python-only, and its `SafetyError` aborts the whole run | `orc/gitops.py` |
| D11 | rate-limit detection substring-scans the whole transcript, so a task about rate limiting can mark its own pool exhausted | both adapters |
| D12 | dead `ladder.retry_count`; `sys.argv[1:2] == ["quota"]` dispatch; report hardcodes `"→ standard:"` and never shows the triage decision; neither adapter sets `stdin` | `orc/cli.py`, `orc/report.py`, adapters |

D10's abort behavior is **kept deliberately**: test tampering remains a hard `SafetyError`
that ends the run. Only its scope is fixed — enumerate via `git ls-files`, not `rglob`.

## 5. Testing the subprocess boundary

Two layers, because neither alone catches both failure modes:

- **Golden fixtures, in CI, free and offline.** Real recorded CLI output under
  `tests/fixtures/`, seeded from §7 below. Catches parser regressions and format drift.
- **`@pytest.mark.live`, opt-in.** Runs each adapter's actual argv against the real CLI
  with a trivial prompt. Deselected by default. This is what caught D1 in five seconds for
  zero tokens — the CLI's own argument parser rejected the combination before any API call.

Asserting the built argv against a hand-written expected list is explicitly **not**
sufficient: it would have passed, because it would encode the same wrong assumption twice.

## 6. Agent context

The Claude adapter's `--safe-mode` disables CLAUDE.md, so Claude ran blind to repo
conventions while `codex exec` read `AGENTS.md` natively — a handicap orc imposed on one
vendor inside a system built to compare vendors.

Verified A/B in a scratch repo whose `CLAUDE.md` contained a codeword:

```
--setting-sources project  →  XYLOPHONE-7742
--safe-mode                →  NONE
```

Each CLI now reads the target repo's instruction files natively, as it would if run by
hand. `--setting-sources project` keeps the owner's global settings, hooks, and plugins out
of the run.

## 7. Probe evidence

Captured 2026-09-07. Extract to `tests/fixtures/` during implementation.

`codex exec --json --approve-for-me` — one shell command and one file edit:

```
{"type":"thread.started","thread_id":"01a07d00-c866-79c3-9645-877ccb9aae60"}
{"type":"turn.started"}
{"type":"item.completed","item":{"id":"item_0","type":"agent_message","text":"..."}}
{"type":"item.started","item":{"id":"item_1","type":"command_execution","command":"/bin/zsh -lc \"echo hello-from-codex && printf '\\n# touched\\n' >> a.py\"","aggregated_output":"","exit_code":null,"status":"in_progress"}}
{"type":"item.completed","item":{"id":"item_1","type":"command_execution","command":"/bin/zsh -lc \"...\"","aggregated_output":"hello-from-codex\n","exit_code":0,"status":"completed"}}
{"type":"item.completed","item":{"id":"item_2","type":"agent_message","text":"Done."}}
{"type":"turn.completed","usage":{"input_tokens":40157,"cached_input_tokens":30208,"cache_write_input_tokens":0,"output_tokens":156,"reasoning_output_tokens":0}}
```

Notes for the parser: `item.started` and `item.completed` both carry the same item id, so
counting tool calls by keyword double-counts — count distinct completed item ids instead.
File edits may arrive as `command_execution` (shell) or as a patch item, so both must count.

`claude --print --output-format stream-json --verbose` yields `system/init`,
`assistant` with `tool_use` blocks (`name`, `input.command`), `user` with `tool_result`,
`rate_limit_event`, and a final `result` carrying `total_cost_usd` and `usage`.

Auth probes, both confirmed correct in the baseline: `claude auth status` returns JSON with
`loggedIn` (and `subscriptionType`); `codex login status` prints `Logged in using ChatGPT`
and exits 0.

## 8. Out of scope

Unchanged from `SPEC.md` §12's non-goals. Specifically not in M2: the review protocol and
consult mode (M3), the Copilot adapter (M4, CLI not installed), token-to-unit cost
modelling, and any preference-based lane selection.
